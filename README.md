# Jarvis

Jarvis is a voice assistant for Home Assistant, written in Rust. It runs as a Wyoming server that gives HA speech-to-text, text-to-speech and a conversation agent in one process.

A small local model (System One) classifies each request and tags its slots. Common commands and questions run locally, with a target response latency of 300 ms (p95) on a GPU host. When System One is not sure, Jarvis sends the request to OpenAI (System Two), which can call HA services and plugins. Each satellite has an area, so "turn on the lights" controls the lights in the room you are in.

The design is in [`docs/spec/`](docs/spec/00-overview.md).

## Capabilities

"Local" requests run on System One. "OpenAI" requests go to System Two.

| Area | Example requests | How |
|---|---|---|
| Lights and fans | "Turn on the lights", "Turn off the kitchen lights", "Turn on the office fan", "Turn off the fan" | Local |
| Climate | "Turn the air down", "Make it warmer" | Local |
| Home status | "Which lights are on?", "How bright is the office light?", "Are any windows open?", "Is the front door locked?", "Is the garage door open?", "What is the thermostat set to?", "Is the fan on?", "Who is home?", "Is the alarm set?", "What is the temperature in the bedroom?" | Local |
| Weather | "What is the weather like?", "Will it rain today?" | Local, Open-Meteo plugin |
| Music (Music Assistant) | "Play hip hop", "Play jazz in the kitchen", "Play Radiohead", "Play music like Miles Davis", "Queue Abbey Road", "Next song", "Previous song", "Pause the music", "Resume the music", "Turn it up", "Set the volume to 50", "What is playing in the living room?" | Local. "Play" searches your library playlists first, then artists, albums and tracks. An artist starts with one of its tracks, and the rest of the artist follows in the queue. |
| Speaker groups (Music Assistant) | "Play jazz downstairs", "Play Christmas music downstairs", "Play Radiohead on the downstairs speakers", "Pause the music downstairs", "Turn it up downstairs" | Local. A place that is not an HA area but matches a Music Assistant group name plays on the whole group. A control acts on the group when the group plays, else on the members that play. |
| TV and Plex | "Play Bluey on the TV", "Put on The Matrix", "Continue The Office", "Play season two episode five of The Office", "Pause the TV", "Skip ahead", "Stop the movie", "Turn off the TV", "Are there any new shows?". With the Plex plugin, Jarvis matches the spoken title to the Plex library ("Vision Quest" plays "VisionQuest", a movie plays as a movie) and says when a title is not in the library. | Local, Plex plugin |
| Follow-up questions | "Turn on the lights" from a device with no area: "Which room?" "The kitchen." Say "never mind" to cancel. | Local |
| Everything else | Any other request, for example "Plan dinner for tonight" | OpenAI, with HA tools and plugins. OpenAI can ask you a question and use your answer. |
| Speech | Streaming speech-to-text, then a second pass at the end of speech. The second pass prefers the names of the house, the command verbs and the playlists, artists and albums of the Music Assistant library, refreshed each hour. Text-to-speech with a cache of rendered responses. A short answer like "Kitchen" ends listening after 100 ms. | Local |
| Responses | Each intent has a pool of replies with variety. Jarvis adds new replies when a pool runs low. A slow request gets a filler reply, then an announcement of the answer. | Local, OpenAI for new replies |
| Interaction log | Jarvis records each request with its audio, transcript, prediction, decision, service calls, responses and latency in the SQLite file `log.database` (`jarvis.db`). For a voice request, it adds the identified speaker, the signal that identified the speaker, and the voice embedding, also when no speaker is identified. Once a day, it deletes audio older than `log.audio_days` and unmarked records older than `log.record_days`. The voice embedding stays as long as its record. | Local |
| Review | A web server on `web.listen` (port 10701) lists the logged requests, gives their audio as WAV and takes good or bad marks with an optional correction. `api/status` gives the status of Jarvis (`online`, `training`, `restarting` or `offline`) and an optional message. Each request under `api/` needs `Authorization: Bearer <token>`, with the token of `web.token_env`. `/` is the review page: it shows the status of Jarvis, or `offline` when Jarvis does not answer, plays each request and marks its action with one click. Each voice request has a person list that shows its speaker: pick who spoke, and Jarvis moves the voice sample of the request to the profile of that person at once, or removes it with the empty choice. A pick wins over the speaker that Jarvis identified. A speaker that Jarvis found shows its source, for example "Louis (voice)": pick the plain person to confirm it and add the voice sample. The page sends no token, so it works only behind a proxy that adds the header, such as the Jarvis app. | Local |
| Training | Each `train.check_interval_s` (10 minutes), Jarvis counts the action marks and the learned intents activated since the last training run. At `train.min_changes` (20), it trains a new System One model with the Python of `train.python` on the marked requests, the examples of `intents.toml` and of the active learned intents, and the examples that OpenAI generates for each of these intents (`train.generated`). During the local run, the status of Jarvis is `training`, and Jarvis mutes each satellite that is not muted (its `_mute_microphones` switch), frees its models for the GPU and does not answer. After the run, it loads its models again, unmutes the same satellites and shows `online`. When its models do not load again, Jarvis stops with the error, and the service manager starts it again. When the local run fails and `[train.runpod]` is set, the same examples train on RunPod. It measures the new and the old model on held-out examples and uses the new model only when it is not worse. The new model is a folder of `model.dir` with the start time of the run as its name. `train.state` (`training.json`) names it, so Jarvis loads it after a restart. Jarvis keeps the current and the previous model folders and deletes the others. After a failed run, the next automatic run waits `train.failure_backoff_s` (6 hours). Say "Start training" to start a run at once, at any mark count. When a run is active, Jarvis replies that training is already running. | Local, OpenAI for generated examples, RunPod after a local failure |
| Learned intents | Each `learn.check_interval_s` (1 hour), Jarvis groups the requests of the last `learn.window_days` (14) days that OpenAI answered. For each new group of `learn.min_cluster` (5) or more similar requests, OpenAI proposes a new intent, and Jarvis saves it in `learn.file` (`learned.toml`): `active` without an HA service, `pending` with a service (it waits until you approve or reject it in the Jarvis tab), `requested` when it needs a new plugin, or `none` when the requests do not suit an intent or the proposal is not valid. A group gets one proposal only. An `active` intent, and one that you approve, gets its replies with pre-rendered audio, and a correction in the review can name it. When the System One model gives the intent, Jarvis replies from its pool locally. The next training run adds an active intent to the System One model. | OpenAI |
| Prefetch | For an active learned intent of the kind `prefetch` with a usual time of the week (from the request habits), Jarvis asks OpenAI its question each minute from `learn.prefetch_lead_min` (5) minutes before the usual hour to the end of that hour, at most once each `fresh_min` of the intent. OpenAI can call only the HA services of `learn.prefetch_services` (`calendar.get_events`), and any other call discards the answer. Jarvis keeps the answer with pre-rendered audio. When the System One model gives the intent from the area of the last such request and the answer is not older than `fresh_min`, Jarvis replies with it at once. Else OpenAI answers as usual. A fetch intent with a usual time, such as "What is the weather like?", gets its plugin result and its reply in the same window, and a fresh reply with the same plugin call and area comes at once, with no filler. | OpenAI, plugins |
| Plugin requests | For a `requested` learned intent, which needs remote data that no plugin gives, Jarvis writes one Markdown file `<intent name>.md` into the folder `learn.plugin_requests` (`plugin-requests`): the requests, their usual times, the data needed and the task for Claude to write the plugin and its fetch intent in a normal PR. Jarvis writes each request once, saves the file path in `learned.toml`, and tries a failed write again at the next check. It does not read, move or delete the files. Without `learn.plugin_requests`, Jarvis writes no requests. After you set it, the next start writes the waiting ones. | Local |
| Settings | The page has a settings form with a fixed list of fields of `jarvis.toml`, in groups, and no secret, URL or path. The group `People` has an "Address as" field for each HA person, which sets `[address]`, and an empty field removes the form of address. `api/settings` gives the fields, and a `POST` saves the changed fields. A save checks the new file with the checks of the start. Jarvis refuses a bad value with a message and does not change the file. During a training run, Jarvis refuses a save as busy, and a training run does not start while Jarvis restarts after a save. After a save, Jarvis keeps the old file as `jarvis.toml.bak` and exits with code 75 to start again with the new values. When that start fails or crashes, the next start puts the old file back, and the status shows `settings rolled back` with the reason. | Local |
| Jarvis tab | The Jarvis app for HA (an add-on before HA 2026.2) puts the review page into the HA sidebar through HA ingress, also in the HA companion app outside the house. It sends each request to Jarvis with the token. When Jarvis does not answer, the tab shows "Jarvis is down" and tries again every 10 seconds. | Local, HA app |
| Voice enrollment | Before it replies to a voice request, Jarvis identifies the speaker, with no enrollment step: the only person at home, else the person whose phone or watch is nearest the satellite plus the best voice match (proximity counts 0 when the presence sensor of the room is `off`). When presence or proximity identified the speaker and the request has `speaker.min_enroll_ms` (1.5 s) of voice, Jarvis adds the voice to the profile of that person in `speaker.voices` (`voices.json`, made at the first add), which keeps the newest `speaker.max_samples` (20). From `speaker.min_profile` (5) samples, an add also needs a voice match of `speaker.voice_threshold` (0.6) or more that beats each other profile. A voice match alone never adds a sample. | Local |
| Form of address | Each person can have a form of address in `[address]` of `jarvis.toml`, for example `"person.ali" = "Lady Lang"`. A response of an intent pool can use it, for example `"I will turn on the lights for you, {{ address }}."`. Each command pool of `responses.toml` has two such responses, for example `"Right away, {{ address }}."`, so a command reply addresses the speaker sometimes. A response with `address` may use only `area` and `address` as variables, and a pool with such a response gets no backfill. For a voice request, Jarvis waits for the voice match before it decides, so presence, proximity and voice identify the speaker of the reply and of a System Two answer. When the voice embedding fails, and for typed requests, only presence and proximity identify the speaker. A response with `address` is used only when the speaker has a form of address, so a pool with such a response must also have one without it. Jarvis pre-renders these responses for each area and each form of address. OpenAI gets the line `Address the user as <address>.` after its system prompt, so a System Two answer can address the speaker too. | Local |
| Status entity | With `[mqtt]`, Jarvis publishes its status as the HA entity `sensor.jarvis_status` through MQTT discovery, with a retained state. The broker sets `offline` when Jarvis stops or dies, and the entity stays after an HA restart. | Local |

Jarvis records each request that System One acts on with its time of the week (request habits, phase 11), and prefetch uses these habits. Not built yet: timers (phases 13 to 16 in [`docs/spec/00-overview.md`](docs/spec/00-overview.md)).

## Quickstart

You need:

- A Linux x86-64 host. An NVIDIA GPU is optional (see step 7).
- Home Assistant with a long-lived access token, and voice satellites.
- An OpenAI API key.
- Optional: Music Assistant for music, and a Plex server and token for TV.
- To build the System One model: Rust, [`just`](https://github.com/casey/just) and Python 3.12.

Steps:

1. Clone the repository at a release tag, for example `git clone --branch v0.1.15 https://github.com/louislang/ha-jarvis.git jarvis`.
2. Download `jarvis-<tag>-x86_64-unknown-linux-gnu.tar.gz` from the [releases](https://github.com/louislang/ha-jarvis/releases) and extract it in the repository folder. It contains the executable and its shared libraries.
3. Download the speech models with `just models`.
4. On a GPU host, run `just gpu-models`. It needs the fp16 speech models in `/opt/jarvis-models/fp16/`. No download has them: convert them once from the fp32 exports, as `docs/spec/phase-06.md` sub-phases 6.6c and 6.7 describe.
5. Build the System One model with `just install-python`, then `just fixture-model`.
6. Edit `jarvis.toml`: set `ha.url`, `plugins.plex.url` and `mqtt.url` (your MQTT broker, for example the Mosquitto broker app of HA). Remove the `[plugins.plex]` section if you have no Plex, and the `[mqtt]` section if you want no status entity. Set `learn.plugin_requests` to a folder that Jarvis can write and Claude Code can read, or remove it to write no plugin requests. The people of the house are the `person` entities of HA, so `jarvis.toml` lists no people. Jarvis finds their phone and watch trackers from HA: the `device_tracker` entities of the person, and on each tracker device the sensor whose state is an area name and the sensor with the unit `m`. To use other sensors for a person, add a `[[people]]` entry with `person` and `trackers`. Jarvis also finds the presence sensors of each satellite: the `binary_sensor` entities on the satellite device with the device class `occupancy`, `presence` or `motion`. Set the device class in HA, or add a `[[satellites]]` entry with `satellite` and `presence` to list the sensors.
7. On a host without a GPU, copy `jarvis.toml` to `jarvis.local.toml` and use that file. In it, set `device = "cpu"`, change `.fp16.` to `.int8.` in `asr.encoder`, `asr.decoder` and `asr.joiner`, and remove `second_pass_dir`.
8. Create `jarvis.env` with `HA_TOKEN=...`, `OPENAI_API_KEY=...`, `JARVIS_WEB_TOKEN=...` (a random token for the review API from `openssl rand -hex 32`) and, for Plex, `PLEX_TOKEN=...`. For `[mqtt]`, add `MQTT_USERNAME=...` and `MQTT_PASSWORD=...` of a broker user. The `[train.runpod]` section is commented out: it is the RunPod fallback of the training run. To set it, remove the `# ` in front of its lines, set its endpoint and volume, and add `RUNPOD_API_KEY=...`, `RUNPOD_S3_KEY=...` and `RUNPOD_S3_SECRET=...` of your [RunPod](https://www.runpod.io) account. Add `LD_LIBRARY_PATH=<folder>` and `ORT_DYLIB_PATH=<folder>/libonnxruntime.so`, where `<folder>` is the repository folder.
9. Start Jarvis: `set -a; . ./jarvis.env; set +a; ./jarvis serve jarvis.toml` (or `jarvis.local.toml`). It listens on port 10700 (Wyoming) and port 10701 (review page and API). After the first HA snapshot, it logs a discovery report: one `discovery:` line for each satellite with its presence sensors, and one for each HA person with their trackers. A device tracker without both sensors shows as `(untracked)`.
10. In Home Assistant, add the Wyoming Protocol integration with the host of Jarvis and port 10700.
11. Create an Assist pipeline with Jarvis as the conversation agent, speech-to-text and text-to-speech. Turn off "Prefer handling commands locally". Select this pipeline on your satellites.
12. For the Jarvis tab, open Settings, Apps in HA (Add-ons before HA 2026.2), open the app store, open Repositories and add `https://github.com/louislang/ha-jarvis`. Install the app Jarvis. Set the option `url` to the web server of Jarvis, for example `http://192.168.1.65:10701`, and the option `token` to the value of `JARVIS_WEB_TOKEN`. Start the app and turn on "Show in sidebar".

To run Jarvis as a service, use a systemd unit with `WorkingDirectory` set to the repository folder, `EnvironmentFile` set to `jarvis.env`, `ExecStart=<folder>/jarvis serve jarvis.toml`, `Restart=on-failure` and `RestartForceExitStatus=75`, so that a save of the settings or a failed load of the models after a training run restarts Jarvis.

## Development

`CLAUDE.md` has the working rules and `docs/spec/02-rules.md` has the required checks. Run `just setup` once, then `just check` runs the checks of the pre-commit hook.
